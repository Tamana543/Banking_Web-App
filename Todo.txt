12.10 — Backend Fixes
work through in this order — top of list first:

*   Move "cors" from root package.json into backend/package.json (npm install cors --save inside backend/) ✔️  
*   Add .env (or backend/.env) to the root .gitignore — it is not excluded right now ✔️
*   Rotate JWT_SECRET and MongoDB credentials, in case .env was ever committed to GitHub history before the .gitignore fix✔️ 
*   Fix free-money exploit: savingsGoalControllers.addSavingsContribution (route: POST /api/savings-goals/:id/contribute) never deducts user.balance and has no PIN check — either delete this route or rebuild it to match transactionController.addMoneyToSavingsGoal ✔️
*   Fix applyLoan NaN bug: swap the inline amount check for isValidPositiveAmount(amount) — a non-numeric amount currently corrupts a user's balance to NaN permanently
*   Add transaction atomicity (mongoose session/withTransaction, or guarded atomic $inc) to depositMoney, withdrawMoney, transferMoney, applyLoan, addMoneyToSavingsGoal — right now concurrent requests can bypass balance checks (race condition)
*   Loans currently credit balance instantly at request time even though status is "pending" and the response says "Loan approved" — decide whether approval should gate the balance credit (ties into Phase 13 admin approval)
*   Avatar upload is broken end-to-end: POST /api/auth/avatar has no multer middleware attached, so req.file is always undefined. Wire uploadMiddleware.js into the route, and consolidate with the correct logic already sitting unused in uploadController.js
*   Delete middleware/protect.js — unused, weaker duplicate of authMiddleware.js (no sessionVersion check)
*   Delete middleware/validateRegister.js — unused, and its password policy conflicts with the one actually in use (utils/passwordPolicy.js)
*   Delete controllers/uploadController.js — unused duplicate of authController.uploadAvatar, has leftover console.logs
*   If validateRegister.js is kept instead of deleted: add try/catch around the User.findOne call, and remove the console.log("Existing user:", existingUser) debug line
*   Add a file size limit (limits: { fileSize }) to uploadMiddleware.js's multer config
*   Change addMoneyToSavingsGoal's recorded transaction type from "withdrawal" to something savings-specific, so Analytics categories stay accurate
*   Add a length cap to the loan purpose field (like isValidText's 500-char limit used elsewhere)
*   Add min: 0 to User.balance in the schema as defense-in-depth
*   Consider bumping sessionVersion on logout too (not just password change), so a captured/stolen token can't keep working after the user logs out
